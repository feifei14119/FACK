# 2026-10-14：aiter 单算子真机验证

这是历史案例，不保证其他 shape、驱动或环境的性能。精简原始样本及散列保存在同目录 `20261014.json`，
不依赖被 Git 忽略的历史 `tune_out/`。新运行方法见 `client/aiter/docs/validation.md`。

- 硬件：8 张 MI308X / gfx942 中的 GPU 6，PCI `0001:A5:00.0`，UUID `0x460ffdd2f4d1f04a`。
- aiter：`2abf8aaa44f9d81c88d6153024b21e6931c7f906`。
- Python 3.12.3、PyTorch `2.10.0+rocm7.2.4.git3d3aa833`、Triton 3.7.0、HIP 7.2.53211。
- 镜像仓库 digest：`rocm/atom-dev@sha256:c7a29446b588a1c85aead74be2c9c7e40a84d6d8817215df4da6ac3f50131bf5`，
  整理时从当时机器的 `docker image inspect` 核实。它不是报告里只适用于本机的 image ID。
- 算子：`fp8gemm_bf16_blockscale_BpreShuffle_32x128.co`，M=N=256、K=1024、FP8→BF16、splitK=1。

原始 `.co` 导出的 seed 通过严格回编检查：5984 字节的 .text、KD（排除链接入口偏移）、metadata、ELF flags 一致。
三个重排候选均通过两个随机输入和计时后完整输出比较。筛选后 8 对确认未达到 1% 收益门槛，最终保留原始代码。

对三个实际重排候选中最快的 LDS 延后版本，用上游 `test_gemm` 做 5 对交错比较：

| 测量 | 基线中位数 µs | 候选中位数 µs | 配对收益的 bootstrap 95% 区间 |
|---|---:|---:|---|
| op_test constant/constant | 7.1399 | 6.9166 | [-1.61%, +7.43%] |
| op_test uniform/auto | 7.0791 | 6.8977 | [-2.26%, +7.93%] |
| 后续 client HIP graph | 6.6164 | 6.6224 | [-0.32%, +0.21%] |

20 个 ASM 正确性比较的错误率均为 0；CK、strided CK、Triton 对照也通过。
op_test 表观收益未达到可靠采用条件，不能与 HIP graph 合成一个总分。
历史 5 对的 AB/BA 数量不完全均衡；正式 compare 入口要求偶数对。

## 实际遇到的问题

| 问题 | 已确认原因 / 处理 |
|---|---|
| 宿主机无 torch | 使用独立 ROCm 容器，runner 解释器指向容器实际 venv |
| PyTorch 镜像中的 Triton 3.4 无法导入 aiter | 此固定版本要求 Triton ≥3.6；换到已验证的 3.7 环境 |
| 缺 pybind11/einops/psutil | 首次 JIT 前检查依赖；不在每个候选失败后临时补包 |
| `.amdhsa_reserve_xnack_mask` / SGPR 回编失败 | LLVM descriptor 打印与汇编默认值不一致；修复 co2s，保留严格 KD 比较 |
| correct=None 但 CLI 成功退出 | 修复 eval_candidate，使缺失/失败的正确性返回非零并显示原因 |
| 只传 kernel_name 可能测到另一份 .co | 当前上游 run_asm 不透传该参数；适配显式绑定 symbol，并核验 loader 路径 |
| op_test 只打印失败比例 | 适配显式检查错误率，不能把正常退出当作数值通过 |

历史实现位于本次任务的 `tune_out/`，含固定目录和 seed 哨兵，不能作为正式入口。
本次整理将其改为随仓库提供的环境工具、显式 validate hook、带版本检查的 op_test driver 和配对比较脚本。
正式入口的验证见 [迁移验证记录](20261014-portability.md)，不能把历史测试数量冒充新代码的验证结果。
