## TODO-1：M9 Phase 4 跨尾段协同调度（span_editor）

### 当前状态
- 暂缓（未实现）

### 目的
- 在保持正确性的前提下，探索 prologue 与 epilogue 之间的协同调度空间。
- 补齐当前“分区独立优化”的能力边界，评估跨尾段协同是否在小 trip count 场景下带来稳定收益。

### 计划
1. **范围收敛与安全边界确认**
   - 明确定义可允许的跨区动作（仅同执行次数区段之间移动；禁止改变循环体执行次数语义）。
   - 固化 loop 栅栏策略，保证不引入软件流水语义风险。
2. **实现 `span_editor` 最小闭环**
   - 支持跨 `prologue↔epilogue` 的受限 move/swap。
   - 保持与现有 `legal_window + Verifier + recompute_cfg` 完整兼容。
3. **验证与评估**
   - 先离线验证（合法性、可回滚、无误报）。
   - 再真机 A/B（小 K / split-K / decode 形状），统计收益分布和方差。
4. **决策**
   - 若收益稳定高于噪声门限，升级为默认可选策略；否则维持“可选实验能力”。

## TODO-2：跨 kernel 的技能晋升到 trusted（知识层泛化验证）

### 当前状态
- 未完成（缺第二个真实 kernel 的验证闭环）

### 目的
- 防止 skill 污染与伪泛化，确保知识层“可迁移、可解释、可追溯”。
- 让 M7 知识系统从单 kernel 的 candidate skill，升级为跨 kernel 可复用 trusted skill。

### 计划
1. **引入第二个真实 kernel**
   - 选择与当前 GEMM 结构差异明显的样本（如 MLA/MoE 路线之一）。
2. **建立跨 kernel 评测协议**
   - 统一记录：正确性通过率、性能提升中位数、波动系数、失败类型分布。
3. **定义晋升门槛**
   - 至少两个 kernel 上均通过正确性与稳定性门槛。
   - 性能收益需超过噪声门限且具可重复性。
4. **实现自动晋升/降级流程**
   - candidate → trusted 的自动判定；
   - 发现反例后自动降级并记录证据链。

## TODO-3：精确 CFG meet（分支/汇合/wave specialization 数据流收敛）

### 当前状态
- 暂缓（线性单环 CFG 已验证；复杂 CFG 的精确 meet 未落地）

### 目的
- 让 waitcnt 重算与校验在复杂控制流（分支汇合、多 wave-arm）上保持正确且不过度保守。
- 将当前“线性单环验证可用”扩展为“复杂 CFG 结构可用”。

### 计划
1. **模型设计**
   - 定义 join 点的 meet 规则：
     - outstanding 取并；
     - done frontier 取交；
     - 对 LDS roundtrip/band 语义保持保守正确。
2. **实现 CFG 数据流版本 recompute_cfg**
   - 支持多前驱、多汇合、wave specialization arm 的状态传播与收敛。
3. **验证器对齐**
   - Verifier 增加与 recompute_cfg 同口径检查，避免“重算通过但校验口径不一致”。
4. **样本验证**
   - 用至少一个含明显分叉/汇合的真实 kernel 做真机验证。
   - 对比保守策略与精确 meet 的性能/正确性差异。
